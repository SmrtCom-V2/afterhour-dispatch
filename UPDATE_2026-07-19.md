## What shipped live (Vercel, frontend)

Confirmed live at https://frontend-dun-one-70.vercel.app (HTTP 200, verified).

1. **Service provider guidance fields** — usage note + availability hours now show on the web dashboard's service provider forms, so an on-call worker gets real guidance instead of just a priority number.
2. **Fixed a live crash bug** — the incident detail page's timeline was throwing on every event that had data (`JSON.parse` on an already-parsed object — Postgres JSONB columns come back pre-deserialized from the backend, so parsing again threw). Confirmed this was actively broken in production before the fix.
3. **Added an ErrorBoundary** — if a page hits an unexpected render error now, it shows a "Something went wrong / Reload" message instead of a blank white screen.

## What's committed to git but NOT on the live server yet

The backend server deploys manually (scp + pm2 restart, not git-based), so none of this is live until someone runs that deploy step. Do NOT assume it's active.

1. **Dispatch restart-survival fix** — if the backend process restarts/crashes mid-dispatch (e.g. after calling one service provider but before they respond), the incident used to get stuck in `sp_dispatched` forever with nobody ever contacted again. Now a scheduler job detects orphaned/timed-out dispatch attempts and resumes the SP call sequence, skipping providers already tried. **This is the highest-priority fix to deploy** — it's the one gap that could cause a real emergency to silently never get dispatched.
2. **Wake-up engine race-condition fixes** — two scenarios where overlapping timer ticks could double-ring someone or dispatch after a human already made a decision. Fixed with an atomic claim table and a decision re-check before dialing.
3. **Security fix (IDOR)** — deleting a building↔service-provider link previously wasn't scoped to the requesting company; fixed and verified.
4. **`ai_confidence_override` bug** — a provider-set confidence override of exactly `0` was being ignored (falsy-zero bug), treated as if no override was set.
5. **express-async-errors** added — async route handlers that throw now correctly reach the error handler and return a proper 500, instead of hanging the request forever (this was a systemic gap across ~15 admin routes).
6. **JWT_SECRET fail-fast** — server now refuses to start if `JWT_SECRET` isn't set, instead of silently falling back to a hardcoded default.
7. **Dependency vulnerability fixes** — `npm audit fix` run on both frontend and backend (non-breaking only).

## Incident during this session (self-caused, resolved)

A batched file transfer to the production server briefly overwrote `src/index.js` with the wrong file's contents, causing an ~8 minute outage (server "online" per pm2 but not actually serving requests). Root-caused and fixed same session; full recovery verified via live health check, login, and an authenticated API call. Lesson applied: never batch-transfer files sharing a basename (`index.js` appears in both `src/` and `src/config/`) — transfer and verify (md5sum) one at a time.

Took several attempts to get the dashboard field to save cleanly. Fixed and verified via API — deploys should work normally now via `git push` to `master`.
